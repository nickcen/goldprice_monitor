# API 服务功能与接口清单

返回 [API 服务](API_SERVICE.md)。依据 [桌面端功能说明](DESKTOP_FUNCTIONS.md) 和 [管理后台功能说明](ADMIN_FUNCTIONS.md) 整理。下列路径为建议契约，实施时应在 OpenAPI 中固定请求、响应和错误码。

## 1. 公共认证与会话

| 方法与建议路径 | 使用方 | 功能与主要数据 |
| --- | --- | --- |
| `POST /api/v1/auth/register` | 桌面端 | 使用手机号、密码注册；规范化并校验手机号，检查重复号码，保存密码哈希。 |
| `POST /api/v1/auth/login` | 桌面端 | 使用手机号、密码登录；校验账号状态及有效期，返回 JWT、过期时间和必要的用户信息。 |
| `GET /api/v1/auth/session` | 桌面端、管理后台 | 校验当前 JWT，返回身份、角色和有效期，供启动或进入页面时恢复登录状态。 |
| `POST /api/v1/auth/refresh` | 桌面端 | 校验当前会话并签发新 JWT，返回新令牌及过期时间；支持每小时刷新和休眠恢复后的补刷新。 |
| `POST /api/v1/auth/logout` | 桌面端、管理后台 | 使服务端可撤销的会话或刷新凭据失效；客户端同时清除本地凭据。若采用纯无状态 JWT，应在契约中说明登出的服务端语义。 |
| `POST /api/v1/admin/auth/login` | 管理后台 | 使用管理员账号、密码登录，校验管理员身份，签发仅能访问授权资源的 JWT。 |

普通用户 JWT 不得访问管理接口。所有受保护接口均需在服务端校验令牌、账号状态、有效期和操作权限；未认证返回统一的未授权错误，权限不足返回禁止访问错误。密码与令牌不得写入日志或响应中的非必要字段。

## 2. 桌面端：用户配置与金价

| 方法与建议路径 | 功能与主要数据 |
| --- | --- |
| `GET /api/v1/me/config` | 返回用户等级、监控频率、低价阈值、高价阈值、金价数据 URL，以及价格的单位、币种和精度；阈值可为空。 |
| `PATCH /api/v1/me/config` | 更新当前用户的低价和高价阈值；允许分别设置或清除。校验非负、精度，以及两项都有值时低价小于高价。返回已保存配置，供客户端重建监控任务。 |
| `GET /api/v1/gold-price/latest` | 当配置的金价 URL 指向 API 服务时使用：返回最新金价、单位、币种、精度和数据时间；数据源失败时返回稳定错误，客户端保留上次成功价格。 |

桌面端按配置返回的金价 URL 定时获取价格，该 URL 可指向上述 API 接口，也可指向外部金价数据源。指向 API 服务时，由服务端接入并规范化外部数据；指向外部数据源时，由桌面端直接请求。正式契约须定义配置 URL 的数据格式、鉴权方式、允许访问范围、缓存与错误处理，并保证阈值与金价使用相同的单位、币种和精度。监控定时器、越界判定与桌面通知由桌面端执行，无需通知发送接口。

## 3. 管理后台：用户管理

| 方法与建议路径 | 功能与主要数据 |
| --- | --- |
| `GET /api/v1/admin/users` | 分页查询用户；按手机号或状态筛选。返回用户 ID、手机号、等级、状态、有效期起止值和创建时间，以及分页信息。 |
| `PUT /api/v1/admin/users/{id}/password` | 修改指定用户密码；校验新密码，仅保存哈希，不返回原密码或哈希。确认密码一致性由前端校验，服务端仍校验密码规则。 |
| `PATCH /api/v1/admin/users/{id}/status` | 将状态设为可用或不可用；校验枚举值，返回保存后的状态。 |
| `PATCH /api/v1/admin/users/{id}/validity` | 修改 `valid_from_date` 和 `valid_to_date`；任一侧可为空，两侧均有值时结束日期必须晚于开始日期，返回保存结果。 |

## 4. 管理后台：支付记录查询

| 方法与建议路径 | 功能与主要数据 |
| --- | --- |
| `GET /api/v1/admin/payments` | 分页查询支付记录；按用户、系统支付单号、创建时间范围和支付时间范围筛选，两个时间范围可同时使用，默认按创建时间倒序。返回支付记录 ID、用户、商品、系统支付单号、可为空的第三方支付单号、可为空的支付时间及创建时间。 |

当前范围仅提供查询。支付状态、渠道、实付金额、退款及支付写入接口须待支付流程和数据模型确定后设计。

## 5. 管理后台：商品管理

| 方法与建议路径 | 功能与主要数据 |
| --- | --- |
| `GET /api/v1/admin/skus` | 分页查询商品；按名称或状态筛选，默认按排序值升序、ID 升序。返回 ID、名称、价格、状态、排序值及创建时间。 |
| `GET /api/v1/admin/skus/{id}` | 返回商品详情。 |
| `POST /api/v1/admin/skus` | 新增商品，提交名称、价格、状态和排序值，返回新商品。 |
| `PUT /api/v1/admin/skus/{id}` | 编辑商品名称、价格、状态和排序值，返回保存后的商品。 |
| `DELETE /api/v1/admin/skus/{id}` | 删除无支付记录关联的商品；存在关联时拒绝删除，并返回可提示管理员改为停用的冲突错误。 |

商品价格单位为分，必须为非负整数；状态只能为可用或不可用。服务端对所有写操作执行参数校验和权限校验。

## 6. 接口契约与待统一事项

- 所有列表接口由服务端分页，每页固定 10 条；统一页码参数、总数和总页数的响应字段。筛选条件、默认排序和时间范围边界写入 OpenAPI。
- 统一 JSON 字段命名、成功和错误响应结构、错误码、JWT 传递方式及各角色权限。常见错误包括参数无效、号码重复、凭据错误、未授权、权限不足、资源不存在、删除冲突和数据源不可用。
- 金价及阈值使用精确十进制表示，契约明确单位、币种、精度和空阈值的表示方式。商品价格使用整数分。
- 时间戳使用带时区的 ISO 8601 格式，服务端统一 UTC，展示时由客户端转换。用户有效期精确到日，`valid_from_date` 和 `valid_to_date` 使用 `YYYY-MM-DD` 日期字符串，不做时区转换；有效区间为 `[valid_from_date, valid_to_date)`，两侧均有值时结束日期必须晚于开始日期。
- 明确 JWT 及刷新凭据的有效期、轮换与撤销策略，保证每小时刷新和主动登出的行为可实现。
- 桌面端自动更新由 Tauri 更新机制处理；更新地址、公钥和签名由构建配置提供，不属于业务 API。若更新元数据由本服务托管，另行定义版本清单与下载接口。
