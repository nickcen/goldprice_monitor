# 公共约定

返回[工程架构](../PROJECT_ARCHITECTURE.md)。

## 项目边界

- 管理后台与桌面应用均使用 API 服务，不直接访问服务端数据库。
- 服务端负责业务规则、数据持久化及权限校验；客户端负责各自的交互和展示。
- 三个项目各自维护构建配置、依赖、环境配置示例和运行说明。跨项目协作依赖 API 契约，不直接引用彼此的内部代码。

## API 契约

- API 服务统一定义接口路径、请求与响应结构、错误码及鉴权方式。建议使用 OpenAPI 文档维护契约。
- 对外接口统一使用 JSON。字段命名、时间格式、时区、金额单位与精度应在接口文档中明确。
- 处理金价等精确数值时避免浮点运算造成精度损失。
- 破坏兼容性的接口变更应有明确版本策略，并同步更新两个客户端及接口文档。
- 客户端通过环境或应用配置设置 API 基础地址。

## 配置与安全

- 区分开发、测试和生产环境配置；真实密钥与凭据不得提交到仓库。
- API 服务执行最终鉴权和权限校验。客户端不存储服务端密钥。
- 日志与错误信息不得泄露密码、令牌等敏感信息。

## 开发与交付

- 各项目 README 提供启动、构建、测试命令及所需运行环境。
- 涉及 API 字段或行为的修改，应同步更新接口文档和受影响客户端。
- 提交前完成变更项目的构建及相关测试；跨端功能验证 API 与两个客户端的交互。
- 部署环境确定后补充发布、监控告警和数据库备份方案。
